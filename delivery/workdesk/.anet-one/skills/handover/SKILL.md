# 交接摘要

接手做到一半或被退回的任务时,缺的不是任务名,是背景。这份摘要就是补这段背景。

## 结构

```
交接:<事项>
  项目与阶段:
  原负责人 / 接手人 / 交接日期:
  为什么交接:(休假 / 调整分工 / 被退回 —— 被退回要写退回原因)

一、这件事要达成什么
二、已经做过什么        每条带时间和产出物位置
三、当前卡在哪          在等谁、等什么、已等多久
四、接手后要做什么      按先后排,标出哪些有前置依赖
五、相关人与资料        外部对接人、文件路径、历史沟通在哪
六、尚未确定的事         谁能改期限、完成标准是什么、谁确认完成
```

## 规则

- 第二块必须给出产出物的位置(文件路径或沟通记录),不能只说"已沟通过"。接手人无法
  凭"已沟通过"继续往下做。
- 被退回的任务,退回原因写在最前面。不写原因的交接会让接手人重复踩一次。
- 第六块不要省。客户场景里"谁有权交办、转交和确认完成"本身尚未确定,把它留空等于让
  接手人再撞一次同样的问题;列出来才能去问。
- 不要替原负责人下结论。他的判断写成"原负责人认为…",与事实分开。
- 从台账生成时,`来源` 列的沟通记录要带进第五块。

## 写完之后

在台账主表里把该行 `负责人` 改成接手人,`交办人` 保持原样,并在「变更日志」记一行,
`依据/来源` 填这份交接摘要。只改摘要不改台账,台账就会继续指向原负责人。
