# 一页纸汇报

读项目台账(`project-ledger` 技能规定的那份 xlsx),输出一页能看完的汇报。

## 结构

```
<项目名> 进展汇报 · <日期> · <汇报人>

一、本期进展
  - 事项 —— 做到哪一步(完成依据)
二、等外部反馈
  - 事项 —— 在等谁,什么时候交出去的,已催过几次
三、需要您决定
  - 事项 —— 背景一句 / 可选方案 / 不决定的后果 / 期望答复时间
四、仅供知情
  - 一句一条,不要展开
```

## 规则

- 第三块只放台账「待决事项」里 `类别 = 需要批准` 的行。`专业判断` 类不要放进来 ——
  那是技术人员该定的事,上报等批示只会把它卡住;`只需知情` 类放第四块。
- 第二块每条都要写"什么时候交出去的",否则看不出已经等了多久。
- 进展只写有 `完成依据` 的。没有依据的事项写在第一块会让汇报失真;它应该还在
  「进行中」。
- 一页的意思是一页。超出时先合并同一阶段的事项,再砍第四块,不要缩字号。
- 台账里 `确认状态 = 待确认` 的内容,在汇报里要带上"待确认"字样。把它写成确定的
  进展,等于用汇报替使用者做了确认。
- 不要加"预计""有望"这类对未来的判断,除非台账里有对应的正式期限。

## 输出格式

默认 Markdown 直接贴进微信或邮件。要 docx/pptx 时用 `docx` / `pptx` 技能,内容不变。
