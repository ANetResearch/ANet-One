# 汇报 PPT

用 `pptx` 技能(`skills/pptx/SKILL.md`)出文件,本技能只规定内容怎么组织。

交付 `.pptx` 而不是图片或 PDF:客户明确提出成果要可继续编辑。

## 先问清三件事

模板、篇幅和阅读人决定整份材料的结构,猜错要整份重做。客户场景文档里这三项都标注
待确认,所以不要自己假定:

- 给谁看 —— 内部汇报、客户沟通、对外交流,三者的详略和口径不同
- 几页 —— 没有页数约束时按下面的默认结构
- 有没有现成模板 —— 有就用,不要另立一套配色

问不到就按默认结构做,并在交付时写明用的是默认结构。

## 默认结构

| 页     | 内容                                                                               |
| ------ | ---------------------------------------------------------------------------------- |
| 封面   | 项目名、日期、汇报人                                                               |
| 结论页 | 三到五条结论。放在最前面,不放在最后                                                |
| 进展页 | 从台账的 `状态` 汇总:做完了什么、在做什么                                          |
| 卡点页 | 台账里 `状态` 为 `等外部反馈` / `等内部决定` / `等领导批示` 的事项,写明 `阻塞对象` |
| 待决页 | 待决事项表里 `类别` 为 `需要批准` 的,每条给出 `可选方案`                           |
| 附录   | 数据来源、`访问日期`、`核实状态`                                                   |

结论页在前:汇报对象经常只看前两页。把结论放最后等于没写。

## 一页一件事

一页讲两件事时,读的人会只记住一件,而且不确定是哪一件。页上文字超过约 120 字就该
拆页或改成表格。

## 数字要能回溯

每个数字在附录里给出出处:台账里的事项名,或资料库 `索引.xlsx` 里的 `标题` 与
`链接`。PPT 上不写出处,但附录必须有 —— 被问到"这个数哪来的"而答不上,这份材料在
那一刻就不能用了。

`核实状态` 为 `未核实` 或 `打不开` 的依据,在附录里照实标注,不要省略成已核实。

## 概念图

需要效果图、墙报、展厅示意时用 `concept-image` 技能出图再插入。不要用 PPT 自带形状
拼效果图。

## 表格

台账本身不往 PPT 里整张搬:十三列在投影上读不出来。按卡点页和待决页的口径摘。需要
完整台账时随 PPT 另附 xlsx。
