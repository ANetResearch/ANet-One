# 研究资料库

研究的产出不是一次回答,而是一份能再被用到的记录。判断依据:同一个政策会在文案、
汇报、客户沟通里反复用到,而每次重新查一遍的成本比记下来高。

## 目录布局

```
资料库/
├── 政策/        <地区>-<机构>-<文件名>.md
├── 同业/        <公司名>.md
├── 设备/        <品类>-<型号>.md
├── 技术/        <主题>.md
└── 索引.xlsx    一行一份资料,供检索
```

一份资料一个 Markdown 文件,正文自由;`索引.xlsx` 是找回的入口。只写 Markdown 不写
索引,三个月后就只能靠文件名猜;只写索引不写正文,则结论无处可查。

## 索引列

| 列               | 说明                                                            |
| ---------------- | --------------------------------------------------------------- |
| `标题`           | 资料本身的名字,不是你的结论                                     |
| `类型`           | 政策 / 同业 / 设备 / 技术 之一,与目录对应                       |
| `主题`           | 自定义标签,用于按业务线找回。多个用顿号分隔                     |
| `来源`           | 发布机构或网站名                                                |
| `链接`           | 原文 URL。没有原文链接的(如纸质材料、同事口述)写来源描述        |
| `访问日期`       | 实际打开它的日期。政策会被修订,没有这个日期就不知道读的是哪一版 |
| `核实状态`       | 见下表                                                          |
| `支持结论的原文` | 原文里支持你结论的那一句或那一段,原话照抄                       |
| `归属`           | `个人资料` / `公司资料` / `项目资料`,后者写项目名               |
| `保留期`         | 待确认 —— 客户未给出保留时长                                    |
| `记录人`         |                                                                 |
| `记录时间`       |                                                                 |

## 核实状态

| 值       | 含义                                     |
| -------- | ---------------------------------------- |
| `已核实` | 打开过原文,`支持结论的原文` 是从里面摘的 |
| `未核实` | 还没打开过。结论可能对,但现在不知道      |
| `打不开` | 打开过,失败了。链接失效、被墙、需要登录  |
| `需付费` | 原文在付费墙后                           |

`未核实` 和 `已核实` 不得合并。对接人反馈过的问题是"AI 给出的部分海外链接难以打开,
也难以知道原文哪一处支持了结论" —— 把没核实的写成已核实,正是这个问题本身。

一条结论如果只有 `未核实` 或 `打不开` 的依据,在汇报里要标出来,不能和已核实的结论
并列陈述。

## 写一条资料

1. 先在 `索引.xlsx` 里按 `标题` 和 `链接` 查重。同一份文件不要记两遍;补充内容写进
   已有那条的正文,并更新 `访问日期`
2. 打开原文。打不开就把 `核实状态` 记成 `打不开`,不要改用二手转述再标成 `已核实`
3. 摘 `支持结论的原文`。摘原话,不要改写 —— 改写过的句子回原文里搜不到
4. 正文写三段:原文说了什么、对公司业务的具体影响、还需要确认什么
5. 写 `归属`。个人资料和公司资料混在一处,后面无法按范围共享

## 定期更新

每次更新不新建文件,在原文件追加一节:

```
## 更新 <日期>
- 上期:<上次的结论>
- 本期:<现在的结论>
- 变化:<差在哪,依据哪份新原文>
- 无变化的部分:<明确列出,否则看不出是没变还是没查>
```

"无变化"要写出来。空着会被读成没查过。

**定时执行目前没有实现。** 客户要求"交付的工作能够定时执行",本技能只规定更新的记录
格式,触发要人工发起。TokenBank 侧没有用户可配置的定时任务,也没有到达用户的推送
通道,所以"每日自动更新项目清单"这件事现在做不到。不要在交付说明里写成已支持。

## 刻意留空

客户场景文档里这几项标注待确认,照记为 `待确认`,不要填推测值:

- 资料现在实际存放在哪里、已有多少历史内容
- 哪些属于个人资料、公司资料、项目资料,同事可查阅的范围
- 各类工作的更新周期;"实时关注"允许多大延迟
- 历史材料保留多久、谁可以查看
- 专业内容由谁核对

## 检索

`索引.xlsx` 用 `xlsx` 技能读。按 `主题`、`类型`、`归属` 过滤,再到对应 Markdown 文件
里看正文。文件数少于几百份时不需要建全文索引。
