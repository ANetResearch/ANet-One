# 办公台账技能包

把 `.anet-one/` 整个目录拷到工作目录下即可,ANet-One 会从 `<项目>/.anet-one/skills/` 加载
(`apps/anet-cli/packages/adapters/src/skills/roots.ts`)。不需要构建,也不经插件市场。

```
cp -r delivery/workdesk/.anet-one /path/to/工作目录/
```

七个技能:

| 技能             | 作用                                            | 对应客户场景   |
| ---------------- | ----------------------------------------------- | -------------- |
| `project-ledger` | 多次沟通合并进同一个项目台账,跨日持续更新       | 01 02 03 04    |
| `one-pager`      | 从台账出一页纸汇报,区分知情/待批准/专业判断     | 06,老板 1 2 3  |
| `handover`       | 交接摘要:背景、已做过什么、卡在哪、后续         | 05             |
| `weekly-report`  | 周报生成与润色;润色只改表达不改事实             | 周报           |
| `research-notes` | 研究资料库:目录布局、索引列、引用留痕、更新对比 | 07 08 11 13 14 |
| `deck`           | 台账/汇报/资料做成可继续编辑的 PPT              | 15             |
| `concept-image`  | 概念图/墙报/展厅效果图,按张计费,先草图后终稿    | 16             |

写 xlsx 用仓库里已有的 `xlsx` 技能(`apps/anet-cli/packages/spreadsheets-plugin/skills/xlsx`),
出 PPT 用 `pptx` 技能(`apps/anet-cli/packages/presentations-plugin/skills/pptx`)。本包只规定
表结构、合并规则与内容组织。

## 尚未覆盖的场景

逐项核对客户场景文档后仍然没有实现的部分,不要在交付说明里写成已支持:

| 场景                       | 缺什么                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------- |
| 14 定期更新、01 的提醒     | 没有用户可配置的定时任务,也没有到达用户的推送通道                                   |
| 09 10 12 的检索            | 走模型自带的联网搜索,已验证可用;但没有结果落库的自动化,要靠 `research-notes` 人工记 |
| 老板 4 员工贡献与岗位      | TokenBank 能按成员出用量,但"贡献和岗位判断"没有数据来源                             |
| 老板 5 经营、采购、报价    | 没有数据接入                                                                        |
| 第四部分 专利              | 客户明确有保密顾虑,未设计对应的隔离方式                                             |
| 第五部分 个人/公司资料隔离 | `research-notes` 的 `归属` 列只是标注,没有访问控制                                  |

## 输出上限

台账整表重出一次约 6700 个输出 token(九行台账 + 变更日志,实测)。输出上限不足
时模型会在表格中途截断,而截断的表格看起来仍像一份完整台账。合并时把上限放到
8000 以上。

## 共享

台账是一个 xlsx 文件。三人共用需要把它放在共享目录或 git 仓库里;技能本身不做并发
控制,两人同时改同一份会后写覆盖先写。多人同时编辑的需求目前没有对应实现。

## 刻意留空的字段

客户场景文档里有若干事项标注"待确认",技能要求把它们记为 `待确认` 而不是填推测值:

- 谁可以调整负责人、时间和完成状态
- 工作完成的判断依据
- 历史进度是否保留、保留多久
- 哪些决定属于领导,哪些属于技术人员
- 是否需要提醒及提醒频率

这些要业主确认后才能定。技能把它们收进台账的「待决事项」表,而不是替使用者决定。
